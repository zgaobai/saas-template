# 管理后台与用户中心

服务端 `ADMIN_USER_IDS` 配置已有用户 ID 后，管理员可从用户中心进入后台。`/admin` 默认打开数据总览。返回网站入口位于 Logo 区域，不放在业务菜单中。

## 后台

| 菜单       | 地址              | 数据与操作                                                                                                                |
| ---------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 数据总览   | `/admin/overview` | 最近 24 小时、7 天、30 天的新增用户、生成任务、订单、积分变化，按币种区分实收与退款，以及每日任务趋势。                   |
| 用户管理   | `/admin/users`    | 查询用户与余额，发放积分、停用/恢复账号，跳转该用户的任务、订单、积分流水。不能停用自身或管理员账号。                     |
| 生成任务   | `/admin/tasks`    | 任务状态、工具、预扣与退回积分、提交与完成时间；按需查看输入和结果，不在列表接口加载完整内容。                            |
| 订单与订阅 | `/admin/billing`  | 订单、原支付渠道、金额、站内/渠道编号、订阅状态及已付权益到期时间；单笔“核对支付”复用原渠道回查、身份校验及支付入账流程。 |
| 积分流水   | `/admin/ledger`   | 购买、赠送、生成扣费、失败退回、退款撤回与兑换；可跳转关联任务或订单。                                                    |
| 套餐配置   | `/admin/plans`    | 添加多个按月订阅、按年订阅及积分包，配置价格、每月积分、展示内容、上架状态和支付商品绑定。                                              |
| 兑换码     | `/admin/codes`    | 创建单次积分/套餐兑换码，设置兑换截止期限及月付/年付权益，复制、启用/停用并查看兑换记录。                                          |
| 操作记录   | `/admin/audit`    | 积分调整、用户停用/恢复、套餐修改、订单核对、兑换码创建及兑换等操作。                                                     |

列表按时间及 ID 游标分页，每页 25 条；支持完整邮箱或相关编号精确查询和状态筛选。总览使用限定时间范围，订单金额不作为实收，退款按退款事件发生时间统计，兑换码不会被计入收款。统计日期按北京时间展示。

## 套餐配置与历史权益

数据库 `plan_configs` 是前台价格、新订单、初次钱包赠送和兑换码创建的共同来源，不需要修改代码或重新部署即可更新。免费赠送在账户首次初始化钱包时发放，每个用户只能领取一次；改动配置不补发或撤回已领积分。

默认保留 `starter`（免费）、`creator`（月付）、`pack`（积分包），管理员可添加多个同类或不同计费周期的套餐。前台只读取上架套餐；公开响应不包含支付商品绑定。每个套餐可绑定 Waffo Pancake 商品 ID、Stripe Price ID、Creem 商品 ID 和 PayPal Plan ID。API 密钥仍只保存在环境配置中。旧内置套餐的环境变量映射作为兼容回退。已有套餐类型/周期不可修改，需要其他周期请添加新套餐；币种为 USD。

名称、金额和积分在创建订单时记录快照。改价后，历史订单和现有订阅续费仍按原订单值处理；已创建兑换码也保持原奖励。前台带配置版本提交新购买请求，过期版本会提示刷新。下架阻止新订单，但不影响原付款回调、既有续费与查询。

修改价格不等于修改服务商后台商品。Pancake、Creem、PayPal 等需要对应的渠道产品配置；结算继续执行现有渠道校验，不一致时不会伪造成功。没有真实服务商凭据时，只能验证本地代码与隔离测试，不能声称真实扣费、退款或取消续费已通过。

## 兑换码

兑换码使用密码学随机数生成 6 位大写字母与数字，排除 0/O、1/I；数据库唯一哈希约束与有界重试避免重复。数据库同时保存兑换校验哈希与 AES-256-GCM 密文，管理员列表解密显示完整兑换码并支持复制，不返回哈希或密文。创建请求有唯一 ID，避免网络重试重复创建。

- 积分兑换：一次性增加指定积分。
- 积分包兑换：使用创建时套餐的积分快照，无自动续费。
- 年付套餐兑换：按创建时的每月积分快照发放 12 期。首期在权益生效时发放，后续按生效日的每月同日发放，月末自动取当月最后一天。同套餐未到期时，新一年从已有权益到期后开始，不提前发下一年的积分。用户信息显示下一期时间、积分和期次；后台兑换列表标明每月积分及 12 期。
- 月度套餐兑换：一次发放创建时的套餐积分，授予一个自然月的站内权益，不会创建自动扣费订阅。相同套餐权益在已有已付/已兑换到期时间后顺延。
- 一码仅能由一名用户成功兑换一次，没有人数设置。数据库触发器拦截第二次发放，支持并发抢兑与原用户幂等重试；失败回滚不消耗兑换码。旧多人数码也遵守新规则，保留历史已发奖励。兑换后显示“已兑换”，完整码仍显示并支持复制，不能重新启用；复制不改变状态，后端继续拒绝再次发放。

名额检查、重复保护、积分发放和兑换审计由同一数据库语句与触发器完成，失败会回滚。用户端每个账户每分钟最多 5 次尝试，有可信 Cloudflare IP 时每个 IP 每分钟最多 30 次尝试；查询与操作均验证登录、权限和来源。

| -------- | ----------- | ------------------------------------------------------------------------------------------------ |

| 任务列表 | `/history`  | 仅自己的任务，按关键词和状态过滤，查看输入、结果、预扣及退回积分、完成时间。                     |

兑换成功后，套餐与订单页重新读取余额、套餐和到期时间，切换到兑换记录，并在弹窗保留成功提示。账户概览、套餐与订单、积分流水、任务列表和后台数据列表在重新进入或窗口重新获得焦点时刷新；其他设备不会接收实时推送，需要重新进入或点击刷新。到期时间统一按北京时间精确到秒展示。套餐记录 Tab 写入 URL，刷新保留选中项；订阅、订单和兑换记录采用后端游标分页，每页 25 条，可查看完整历史；各 Tab 独立保留当前页，页面刷新回到该 Tab 第一页。用户端不再展示手动核对付款按钮，支付回调和管理员核对能力保留。

套餐权益过期不等于积分清零。取消续费不立即撤销已支付权益。订阅状态和已付权益时间分开展示。用户 API 始终按当前登录用户 ID 查询，不接受客户端传入其他用户身份。

## 权限与升级

后台页面和接口均验证管理员身份。停用用户会撤销现有会话，数据库阻止创建新会话，受保护 API 拒绝访问；恢复后需要重新登录。密钥仍放服务端环境配置，后台不展示或编辑密钥。

升级需应用 `0005_small_secret_warriors.sql` 和 `0006_slippery_living_lightning.sql`：新增后台索引、套餐配置、兑换表及触发器、账号停用和任务完成字段、订单名称快照。只对本地执行过迁移；云端请使用项目已有 staging/production 迁移流程。

验证覆盖：`admin-queries.test.ts`、`admin-operations.test.ts` 及既有账本/支付测试；隔离 SQLite 验证重复兑换、名额争抢、失败回滚、套餐快照、用户停用、权限、分页、指标及个人数据隔离。`scripts/smoke-local.mjs` 只能在无 AI key 的本地开发环境运行。

## 编号源头长度

新认证账号与用户 ID 使用 128 位随机值的 Base64URL 编码，长度 22 个字符；新增兑换记录同样使用独立 22 位随机编号，兑换积分流水为 `redeem:` 加该编号，共 29 位，不再拼接兑换码和用户编号。同码同用户唯一约束继续保证幂等，旧格式重试仍返回原记录。既有主键、账务关联、第三方订单号不做截断或改写；既有 UUID 请求编号维持 36 位以兼容现有接口。

本地冒烟测试邮箱使用 12 位随机十六进制后缀；不再拼接完整 UUID。正常用户邮箱保留真实地址。源头长度已通过实际注册及兑换检查：新用户 ID 22 位、兑换流水 29 位、前后台余额一致。

界面支付渠道全称为 Waffo Pancake，保留 Stripe、Creem、PayPal，移除旧 Waffo 历史渠道筛选项。Pancake 本身的服务域名和签名协议不变。

兑换码创建改为弹窗：填写积分或套餐奖励，创建后可在弹窗或管理员列表复制兑换码，列表自动刷新；提交期间禁止重复提交和关闭弹窗。兑换码名称和完整码分列，不展示内部编号。查询、重置、刷新统一放在筛选区，分页区只保留条数和翻页。

用户详情的任务、积分流水、订单、兑换记录采用表格展示，沿用后台列表的日期、编号复制和分页组件。任务内容按行展开，空列表保留列标题；查询仍限定目标用户，每页最多 25 条。

## 六位单次兑换码与加密配置

迁移 `0009_single_use_redeem_codes.sql` 新增密文字段和数据库单次兑换触发器，已在本地应用。`REDEMPTION_ENCRYPTION_KEY` 为 32 字节随机值的 64 位十六进制形式；仅存服务端私密环境配置。`npm run setup:local` 会为缺少此项的本地配置生成密钥，保留其他参数。staging / production 分别通过 Cloudflare Secrets 配置；密钥应备份，不能直接替换，否则既有密文无法读取，轮换需先重加密。加密将记录 ID 绑定为附加认证数据，防止交换记录密文。缺少密钥时禁止创建，解密失败不返回伪造码或密文。

旧码只存哈希，无法从哈希还原完整原文；显示“旧码未保存原文”，不提供复制。已经保存的旧版长码仍能兑换，原用户重复请求不再次发放。新短码不重用任何已存在的码，包括已兑换和过期的码。

验证包括短码碰撞重试、管理员访问控制、密文与记录绑定、缺失/错误密钥、旧长码兼容、单用户及多用户并发、账本失败回滚。实际本地 HTTP 验证：6 位码首次仅增加 1 积分，原用户重复提交不加分，第二用户被拒绝，管理员列表显示已兑换状态且拒绝重新启用；后续测试确认已兑换码仍可由管理员读取完整原文。全量 237 项测试通过，未部署云端。


后台用户身份以邮箱为主、昵称为辅：用户、任务、订单、订阅、积分流水、兑换记录及操作记录共用邮箱优先展示。用户详情和发放/停用弹窗同样先显示邮箱，不显示用户内部编号；缺失邮箱明确标记不可用。任务、订单、订阅及流水等业务记录编号仍保留展示与查询能力，不改变底层主键或关联。


兑换记录总列表与用户详情共用五列表格：兑换人邮箱、完整兑换码（支持复制，附名称）、兑换内容（套餐及积分）、权益到期和兑换时间。历史未存原文的码明确标记。服务端仅管理员可读取解密后的码，不返回密文或哈希；总列表支持按完整邮箱或兑换码查询，用户详情保持限定该用户的游标分页。


## 动态套餐与年付按月积分

后台添加/编辑弹窗与前台价格共用 `plan_configs`。年付金额为全年实付价，`credits` 表示每月积分；实际优惠由管理员填写的年价决定，不自动把月价乘以折扣。前台按月付、年付、积分包分组，每组可有多个套餐。套餐类型和周期创建后保持不变。

下单保存名称、金额、每月积分、支付类型、计费周期及商品引用快照。回调依据订单快照发权益，不读取被修改的新套餐价格。Stripe 可以绑定 Price ID，也可保留按站内价动态创建；PayPal 积分包直接创建一次性订单，不使用 Plan ID。其余渠道新套餐必须绑定对应商品，付款前回查商品类型、周期等约束；Creem/Stripe/PayPal 校验价格与币种，Waffo Pancake 使用服务端签名价格快照。

年付成功需有服务商确认的全年起止时间：生成 12 期积分计划，首期到账即发，随后按起始日逐月发放；月底按该月最后一天处理，下一月重新按原始日期计算。Cloudflare 现有每 5 分钟维护任务每批处理最多 100 期，遗漏运行会补发已到期的期次。数据库原子更新与账本触发器防止回调/定时任务并发重复发放。历史订单和已创建分期均保留原积分。

关闭自动续费不取消已付款年度内的积分；全额退款撤回已发积分并取消未发期次；部分退款按退款比例调整已发和后续各期积分。缺失可信全年周期时不猜测到账时间，暂不发放，等待回查。账户注销后不再发放。积分码、积分包和月度兑换保持原奖励规则；年付套餐兑换每月发放一期，共 12 期，不建立自动扣款订阅。

渠道周期字段依据：[Waffo Pancake 官方 SDK](https://pkg.go.dev/github.com/waffo-com/waffo-pancake-sdk-go)、[Stripe Prices](https://docs.stripe.com/api/prices)、[Creem 月/年订阅](https://docs.creem.io/skills/creem-api/WORKFLOWS)、[PayPal Billing Cycles](https://developer.paypal.com/docs/multiparty/subscriptions/customize/billing-cycles/)。真实付款仍需各渠道测试凭据和回调联调，不能用本地测试代替。

## 年付兑换按月发放（0012）

`0012_condemned_gauntlet.sql` 新增兑换分期记录及每月账本触发器。兑换占用、权益顺延、12 期计划、首期到账与审计在同一条写入事务中完成。定时维护每轮最多处理 100 笔到期兑换分期，失败回滚待下轮重试；重复运行不重复发放。注销账户不再发放。用户信息中的“下次积分发放”同时查询付费年订阅和年套餐兑换，显示最早未发期次，已到期但尚未处理时明确提示等待系统处理。

## 同套餐月付 / 年付（0013）

新订阅套餐在同一条配置里维护月价和可选全年总价，共用名称、功能与每月积分。年价不得超过月价 × 12；没有开启年付时前台不会提供该选项。前台年付卡片显示折合月价、全年实付与实际节省金额，不把折合月价作为扣款金额。每种周期分别保存支付商品引用，年付不会回退使用原月付环境商品 ID。公开套餐接口剔除两组支付绑定。

下单必须携带选中的 `interval`，新订单保存选择的周期、全年或月度实付金额、每月积分与商品快照。同一个请求 ID 不允许改周期，未完成月付订单也不能被当成年付订单返回。旧独立年付配置仅供历史记录读取，不再出现在后台套餐列表、前台价格或兑换码套餐选择中。接口禁止新建/编辑独立年付套餐、新下单及新建对应兑换码；既有订单继续查询与处理，已创建的兑换码和分期按原快照兑现。后台统一提供订阅套餐与积分包。

创建兑换码时先选套餐，再选月付/年付权益；月付固定一个自然月，年付固定一个自然年、12 期，无需填写套餐权益天数。启用年付后仍需在当前支付平台创建/选择对应年付商品并填入绑定。停用年付、修改价格或商品不改已有订单和兑换码快照。`0013_careful_layla_miller.sql` 仅新增配置字段，不自动推断、合并或改价历史套餐。

## 固定兑换权益周期（0014）

新建套餐兑换码保存 `term_months` 快照：月付 1、年付 12，积分包和纯积分为 0。创建接口不再接受 `days`，前端仅选择权益周期；“兑换有效天数”仍用于生成兑换截止时间。月度兑换由数据库触发器在同一事务内按日历顺延一个月，月末自动取目标月份最后一天，保留毫秒时间。已有同套餐权益从原到期时间顺延。历史兑换码保留既定天数，历史兑换和账本不重算。
